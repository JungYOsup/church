# TDD 강제: 테스트 먼저 hook과 계획 규칙

## Context
- 왜 하는가: 카카오맵 T1에서 처음 써 본 TDD(테스트를 먼저 쓰고 실패를 본 뒤 구현)를 앞으로 빠짐없이 하기 위해서입니다. 지금은 규칙도 강제 장치도 없어서, 구현을 먼저 쓰고 테스트를 뒤에 붙여도 막을 방법이 없습니다. 기계가 막을 수 있는 부분(로직 파일의 짝 테스트)은 hook으로, 막을 수 없는 부분(모든 task의 테스트 먼저 순서)은 계획 규칙과 run-plan의 증거로 지키게 합니다.
- spec:
  - 무엇을: ① 짝 테스트가 없는 순수 로직 파일은 쓰지 못하게 막는 PreToolUse hook ② Stop hook에서 단위 테스트 실행과 짝 테스트 확인 ③ 계획서 틀과 run-plan에 "task마다 테스트 먼저, red 출력을 증거로"
  - 어디서: `.claude/hooks/`, `.claude/settings.json`, plan-work·run-plan 스킬, CLAUDE.md
  - 완료 조건: 테스트 없는 대상 파일을 Write·Edit하면 실제로 막히고, 짝 테스트가 있거나 대상이 아니면 통과합니다. Bash로 만든 대상 파일과 실패하는 단위 테스트는 응답 종료 때 막힙니다. 새 계획서 틀로 쓴 task에 "테스트 먼저" 항목이 있습니다. `npm run lint && npm run build`와 `npm run test`가 통과합니다.
- 6축 위치: 실행(EX-01 DoD 강제), 검증(VF-01·VF-04 자동 검증), 계획(PL-02 계획 품질)

## 확인한 사실
- **PreToolUse hook (ctx7 `/websites/code_claude`, hooks-guide):**
  - 입력 JSON의 `tool_input.file_path`가 대상 파일의 절대 경로입니다.
  - exit 2이면 도구 호출이 취소되고 stderr가 Claude에게 전달됩니다. exit 0이면 평소 권한 흐름을 따릅니다.
  - 설정은 `"PreToolUse": [{ "matcher": "Edit|Write", "hooks": [...] }]`입니다.
  - 문서 예시(`protect-files.sh`)가 이번과 같은 모양입니다: jq로 경로를 꺼내 패턴을 비교하고, exit 2로 막습니다.
- **기존 hook 관례:**
  - `.claude/hooks/*.sh`는 bash와 jq를 쓰고, `"$CLAUDE_PROJECT_DIR"/.claude/hooks/…`로 연결합니다.
  - `sync-harness-map.sh`처럼 한 스크립트가 옵션(`--mark-synced`)으로 다른 모드를 가집니다.
  - `verify-on-stop.sh`는 `APP_PATHS` 변경의 지문이 마지막 통과와 같으면 건너뜁니다. 재시도(`stop_hook_active`)에서도 실패하면 경고만 띄웁니다. nvm은 스크립트 안에서 불러옵니다.
  - `verify-on-stop.sh`의 `APP_PATHS`에 `vitest.config.mts`가 없습니다. 카카오맵 계획 T4에 이미 적혀 있는 항목입니다.
- **hook 반영 시점(`docs/plans/2026-10-01-stop-hook-verify.md` 60행):** `.claude/`가 세션 시작 때부터 있었다면 새 hook이 바로 반영됩니다. 반영되지 않으면 `/hooks`를 열어 다시 불러옵니다.
- **대상이 되는 `src/lib` 파일:**
  - `geo.ts`는 짝 테스트가 있습니다.
  - `navigation.ts`는 짝 테스트가 없습니다. 다음에 고칠 때 테스트를 먼저 써야 합니다.
  - 제외하는 파일: `types.ts`, `utils.ts`(shadcn이 생성한 `cn`), `mock/`, `data/`
- **스킬 형식:**
  - plan-work SKILL 5단계: Tasks 형식(파일·의존·확인)은 run-plan이 읽으므로 template과 run-plan을 함께 바꿔야 합니다.
  - plan-work 4단계: 지금은 의존 순서를 "… → 테스트 → 문서"로, e2e를 별도 task로 둡니다. 예시의 T3도 따로 떨어진 e2e task입니다. 이 부분이 테스트 먼저 규칙과 어긋납니다.
- **T1 경험(카카오맵 계획서 변경 이력):** 파일이 없어서 나는 "Cannot find package" 실패는 별칭 설정 문제와 구분되지 않았습니다. 그래서 빈 구현으로 "구현이 없어서 실패"를 다시 확인했습니다. run-plan 규칙에 옮길 내용입니다.
- **CLAUDE.md(60줄):**
  - Commands의 `npm run test` 설명이 "Playwright 동작 테스트"뿐이라 단위 테스트가 빠져 있습니다.
  - DoD 57행은 Stop hook이 lint·build만 돈다고 적고 있습니다.

## 결정
- **질문과 답:**
  - 적용 위치: PreToolUse(새로 만듦) + Stop(기존 hook에 추가) 둘 다
  - 엄격도: 약하게(짝 테스트 파일이 있으면 통과)
  - 계획 규칙: 함께 넣음
- **정한 것:**
  - **스크립트 하나로 대상 규칙을 정합니다.** `.claude/hooks/require-test-first.sh` 하나가 두 모드를 맡습니다.
    - 기본 모드: PreToolUse 입력을 받아 검사합니다.
    - `--check <경로…>`: 짝 테스트가 없는 경로를 출력하고 exit 1로 끝냅니다. Stop hook이 이 모드를 부릅니다.
    - 대상 패턴이 한 곳에만 있어서 두 hook이 어긋나지 않습니다.
  - **대상:** `src/lib/**/*.ts`에서 `*.test.ts`, `*.d.ts`, `src/lib/types.ts`, `src/lib/utils.ts`, `src/lib/mock/`, `src/lib/data/`를 뺍니다. 짝 테스트는 같은 폴더의 `<이름>.test.ts`입니다. 프로젝트 밖 경로는 통과시킵니다.
  - **막는 방식:** exit 2와 stderr입니다. 문서 예시와 기존 hook 관례를 따릅니다. 메시지에는 짝 테스트 경로와 할 일(테스트 작성 → 실행해 red 확인 → 구현)을 적습니다.
  - **Stop hook 순서:** 바뀐 대상 파일의 짝 테스트 확인(가장 쌉니다) → `npm run test:unit` → `npm run lint` → `npm run build`. 바뀐 파일은 `git diff --name-only --diff-filter=d HEAD`와 추적하지 않는 새 파일에서 구합니다. 실패 메시지와 상태 줄 문구에 test:unit을 더합니다.
  - **계획 규칙:**
    - template의 task에 `테스트 먼저(red)` 항목을 `의존`과 `확인` 사이에 둡니다.
    - 테스트는 별도의 마지막 task가 아니라 각 task 안에서 구현보다 먼저 씁니다. 로직은 Vitest 단위 테스트, 화면 동작은 e2e입니다.
    - 확인할 동작이 없는 task(문서, 보이는 모습만 바꾸는 작업)는 `해당 없음 — <이유>`로 적습니다.
  - **run-plan:**
    - 3단계에 "테스트 먼저" 단계를 넣습니다. 실패 이유가 "구현이 없어서"인지 확인하고, red 출력 한 줄을 증거로 남깁니다.
    - 이 항목이 없는 예전 계획서는 동작 증거의 테스트를 먼저 씁니다.
  - **카카오맵 T4와 겹치는 것:** `verify-on-stop.sh`의 `APP_PATHS`에 `vitest.config.mts`를 더하는 것과 CLAUDE.md Commands의 test 설명은 이번에 합니다. T4에서는 빼고, 그 계획서 변경 이력에 적습니다. `.husky/pre-commit`은 이번에 바꾸지 않으므로 T4에 남깁니다.
  - 이번 hook 작업도 스스로 테스트 먼저 방식으로 진행합니다. 기대하는 결과를 담은 시험 스크립트를 scratchpad에 먼저 쓰고, 지금 상태에서 실패하는 것을 본 뒤 구현합니다.
