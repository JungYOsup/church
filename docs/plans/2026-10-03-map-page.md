# 교회 지도 페이지 (`/map`)

## Context
- **왜 하는가:** "지역 교회를 지도 위에서 연결한다"가 이 프로젝트의 정체성인데, `/map`은 아직 준비 중 화면이고 홈 지도 칸도 대체 화면뿐이다. 1단계(UI)에서 남은 화면 중 가장 어렵고(외부 SDK, 클라이언트 상태) 포트폴리오에서 가장 먼저 보여 줄 화면이다.
- **spec**
  - 무엇을: 카카오맵으로 교회 지도 페이지. 전체 지도 + 교회 목록 + 지역 필터, 십자가 핀과 이름 라벨, 고른 교회의 사진 오버레이, 지도를 움직이면(`idle`) 범위 안 교회만 남기고 "현재 지도 범위 내 교회 N개". 키가 없거나 SDK를 못 불러오면 대체 화면
  - 어디서: `/map`, 홈 "우리 지역 교회 지도" 칸
  - 완료 조건: 키가 있으면 3000 개발 서버에서 마커가 뜨고 지도를 움직이면 목록·개수가 바뀜. 키 없음·SDK 실패에도 대체 화면과 목록이 나오고 빌드가 깨지지 않음. e2e를 추가하고 `npm run test` 통과. 375 / 768 / 1440px 확인
- 6축 위치: 실행(task 단위 실행), 검증(e2e 추가, 가짜 SDK로 외부 의존 없는 테스트, 일부러 깨뜨려 보기)

## 확인한 사실
- **상위 계획서(1단계 절 전체, 카카오맵 절 81~87행):** `next/script`로 `autoload=false`, `kakao.maps.load()` 뒤 렌더링. 커스텀 마커(십자가 핀)와 이름 라벨, 고른 교회는 사진 오버레이. `idle`에서 범위 안 교회만 "현재 지도 범위 내 교회 N개". 키가 없으면 정적 대체 화면. 라우트 절: `map/page.tsx` = "전체 지도 + 좌측 목록 + 지역 필터". 컴포넌트 절: `map/KakaoMap.tsx ('use client')`. 래퍼(`react-kakao-maps-sdk`)는 "ctx7로 최신 문서를 보고 정한다".
- **참고 이미지(Read로 확인):** 홈 지도 칸에 물방울 핀(흰 십자가) + 흰 알약 이름 라벨, 고른 교회(서연교회)는 핀 위에 사진과 굵은 라벨, 오른쪽 아래 +/− 확대 버튼, 왼쪽 아래 "📍 현재 지도 범위 내 교회 24개" 알약. 지도 페이지 자체의 목업은 없다.
- **카카오맵 공식 문서(ctx7 `/websites/apis_map_kakao_web`):** `sdk.js?autoload=false` 후 `kakao.maps.load(cb)`. `idle`은 중심·레벨 변경이 끝나면 발생. `LatLngBounds.extend()` + `map.setBounds()`로 여러 점이 보이게 맞춤. `CustomOverlay({ content, position, map })`의 content는 HTML(요소도 가능), 닫기는 `setMap(null)`.
- **`react-kakao-maps-sdk`:** ctx7에 없다(두 번 검색). npm 1.2.2(2026-08 갱신, React 19 지원, peer `kakao.maps.d.ts`).
- **Next 16 문서(`02-guides/environment-variables.md`):** `NEXT_PUBLIC_*`는 `next build` 때 번들에 박힌다(이후 바꿔도 반영 안 됨). `process.env.X`처럼 직접 써야 박히고 `process.env[name]`은 안 된다. 찾는 순서는 `process.env` → `.env.production.local` → `.env.local` → …
- **`@next/env` 코드:** 시작 시 `process.env`에 이미 있는 키(빈 문자열 포함)는 `.env.local` 값으로 덮지 않는다.
- **Playwright webServer(`playwright/lib/runner/index.js`):** `env: { ...process.env, ...config.webServer.env }`로 합친다. → `playwright.config.ts`의 `webServer.env`에 키를 주면 `.env.local`과 상관없이 e2e 빌드의 키가 정해진다.

- **배운 점 관련:** 역할 이름 부분 일치(`exact: true`), 검색어에 따른 탭 제목 고정, `next start`와 빌드 동시 실행 금지, `wrap-anywhere`, `role="list"`, `outline-hidden` 포커스.

## 결정
- **질문과 답:**
  - 환경변수 이름 → `NEXT_PUBLIC_KAKAO_MAP_KEY`(`.env.local`에 있음, 읽지 않음)
  - 카카오 콘솔 등록 도메인 → `http://localhost:3000`만. 실제 지도 확인은 3000 개발 서버에서만 한다.
- **정한 것:**
  - **SDK 연결:** `src/components/map/kakao.ts`에 쓰는 API만 담은 타입과 로더 `loadKakaoMaps(appKey)`를 둔다.
    - 로더는 Promise를 한 번만 만든다.
    - 스크립트 `onerror`, `window.kakao.maps`가 없음, 10초 안에 `load` 콜백이 오지 않음은 모두 실패로 본다. 실패하면 Promise를 비워 다음 마운트에서 다시 시도한다.
    - 실패해도 콘솔에 에러를 찍지 않고 대체 화면만 보여 준다.
    - 새 의존성은 없다.
  - **마커:**
    - `CustomOverlay`의 content에 DOM 요소를 주고 React `createPortal`로 버튼을 그린다. 핀은 primary 파랑 물방울에 흰 십자가이고, 이름 라벨은 흰 알약이다.
    - 고른 교회는 핀이 커지고 그 위에 사진 카드가 붙으며 맨 위로 올라간다.
    - 이름 라벨은 지도가 어느 정도 확대됐을 때만 보인다(레벨 기준은 화면에서 겹침을 보고 정하고, 시작값은 8). 고른 교회의 라벨은 늘 보인다.
  - **확대·축소:** 카카오 기본 `ZoomControl`(오른쪽)을 쓴다. 키보드 사용자는 목록과 칩으로 같은 일을 할 수 있다.
  - **크기 변화:** 지도 칸 크기가 바뀌면 `ResizeObserver`로 `map.relayout()`을 부른다. 카카오 문서상 필수다.
  - **목록:** 지도 옆 좁은 칸에 15곳을 세로 카드(`ChurchCard`, 사진 16:10)로 쌓으면 너무 길다. 그래서 작은 줄 `church/ChurchListItem`을 새로 만든다. 썸네일, 이름, 지역, 목사, 인원이 들어간다. 줄 전체가 "고르기" 버튼이다. CLAUDE.md의 "ChurchCard를 지도 목록도 같이 쓴다"는 문장을 고친다.
  - **배치:**
    - 1024px 미만: 지도(약 55svh, 최소 320px) 아래에 목록
    - 1024px 이상: 왼쪽 목록 칸(360px, 혼자 스크롤) + 오른쪽 지도. 높이는 화면 높이에 맞추고, 정확한 값은 화면에서 정한다.
  - **지역 필터:**
    - `?region=서울`을 서버 페이지가 `searchParams`로 거른다. 행사·공지와 같은 방식이다.
    - 칩은 교회가 있는 지역만 보여 주고, 순서는 많은 순(같으면 가나다)이다.
    - 지역이 바뀌면 지도가 그 교회들에 맞춰 `setBounds`한다.
    - 칩에 없는 지역으로 오면 그 글자를 화면에 다시 적지 않는다.
  - **개수 문구:**
    - 지도가 떠 있으면 `/map` 목록 머리(`role="status"`)에 "현재 지도 범위 내 교회 N개"를 적는다. 지도가 없으면 "교회 N개"다.
    - 지도 위 알약은 홈 칸에만 둔다(목업). `/map`은 목록 머리에 이미 적혀 있어 같은 문구가 두 번 나오지 않게 한다.
  - **고르기 상태:** 클라이언트 상태(주소에 넣지 않음). 지역을 바꿔 고른 교회가 목록에서 빠지면 고르기를 푼다.
  - **처음 화면:** 지도는 받은 교회 전체가 보이게 `setBounds`한다. 처음 그린 HTML(서버)에는 목록 전체가 있으므로, 지도가 늦거나 실패해도 목록은 바로 보인다.
  - **e2e는 실제 카카오 서버에 기대지 않는다:**
    - `playwright.config.ts`의 `webServer.env`에 가짜 키(`e2e-fake-key`)를 준다.
    - `e2e/fixtures.ts`에 옵션 fixture `kakaoSdk`를 더해 모든 `dapi.kakao.com` 요청을 가로챈다.
      - 기본 `"unavailable"`은 빈 스크립트를 200으로 돌려준다. 그러면 `kakao`가 없어 대체 화면이 나오고, 콘솔 에러도 외부 네트워크도 없다.
      - 지도 테스트는 `test.use({ kakaoSdk: "fake" })`로 `e2e/kakao-fake.js`(우리가 쓰는 API만 흉내 내고, `window.__fakeKakao.moveTo(bounds)`로 지도 이동과 `idle`을 일으킴)를 받는다.

## 리스크와 멈출 조건
- **3000 포트를 다른 세션이 쓰고 있음:** 등록 도메인이 3000뿐이라 실제 지도를 볼 수 없다. T3의 실제 SDK 확인 전에 `lsof -iTCP:3000`으로 보고, 다른 세션의 서버면 끄지 않고 사용자에게 묻는다.

- **e2e 빌드가 `.next`에 가짜 키를 남김:** `npm run test` 뒤 `npm run start`로 데모하면 대체 화면이 나온다. 데모는 `npm run build`를 다시 한 뒤에 한다. T8에서 문서로 남긴다.
