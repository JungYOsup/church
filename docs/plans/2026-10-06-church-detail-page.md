# e2e 동시 실행 줄이기와 교회 상세 페이지 (`/churches/[id]`)

## Context
- **왜 하는가:**
  - (1) 커밋할 때마다 pre-commit이 전체 e2e를 돌리는데, 칩·탭 클릭 대기가 부하 때문에 5초를 넘겨 가끔 실패합니다. 대표자 관리 커밋 때 한 번 거부됐습니다. 사용자가 고친 방법은 동시 실행 수를 5에서 3으로 줄이기입니다.
  - (2) 교회 상세는 1단계 라우트 중 마지막으로 남은 화면입니다. 지금은 교회 하나를 자세히 볼 곳도, 그곳으로 가는 링크도 없습니다.
- **spec**
  - 무엇을: 교회 한 곳의 소개, 위치 지도, 다가오는 행사, 공지를 보여 주는 페이지
  - 어디서: `/churches/[id]`. 입구는 홈 추천 교회 카드, 지도 페이지에서 고른 교회의 목록 줄과 사진 카드
  - 완료 조건:
    - 교회 15곳마다 페이지가 열리고, 없는 id는 404입니다.
    - e2e를 추가해 `npm run test`가 통과합니다.
    - 375 / 768 / 1440px에서 확인하고, 3000 개발 서버에서 진짜 지도를 확인합니다.
- **6축 위치:** 실행(task 단위 실행), 검증(e2e 안정화, e2e 먼저, 가짜 SDK)

## 확인한 사실
- **Playwright:** `playwright.config.ts`에 `workers`가 없어 기본값(CPU 10개의 절반 = 5)으로 돕니다. 흔들림 측정은 대표자 관리 계획서 변경 이력에 있습니다(개발 서버를 켠 채 3/3 실패, 끈 채 8번 중 2번 실패).
- **상위 계획서:** 라우트 절에 `churches/[id]/page.tsx  # 교회 상세 (소개, 행사, 공지)`가 있습니다.
- **Next 16 문서:**
  - 동적 경로의 `params`는 Promise이고, 타입은 `PageProps<"/churches/[id]">`입니다(`03-file-conventions/dynamic-routes.md`).
  - `generateStaticParams`가 없으면 요청 때 그려집니다(`04-functions/generate-static-params.md`). `cacheComponents`는 꺼져 있습니다(`next.config.ts`). 그래서 "다가오는 행사"가 빌드 시각에 고정되지 않습니다.
  - `notFound()`는 렌더 경로에서 던져 404 화면을 그립니다(`04-functions/not-found.md`). `src/app/not-found.tsx`는 없어 Next 기본 404가 나옵니다.
  - 탭 제목 틀은 layout의 `"%s | 함께하는 교회"`입니다. 배운 점의 "탭 제목 어긋남"은 검색어(`?tag=`) 문제였습니다. 경로 값은 경로마다 따로 담기므로 `generateMetadata`로 교회 이름을 탭 제목에 넣습니다.
- **데이터:** 이미 있는 함수로 충분해서 새 데이터 구조는 없습니다.
  - `getChurch(id)`(없으면 `null`)
  - `getUpcomingEvents({ churchId })`, `getRecentNotices({ churchId })`
  - 서연교회(`church-1`)는 행사 1개(청년 연합 찬양집회), 공지 1개입니다.
  - 빛과소금교회(`church-7`)는 행사·공지가 모두 없습니다(목데이터 churchId로 확인). 빈 안내를 시험할 때 씁니다.
- **지도(`ChurchMap`):** 받은 교회 모두에 `setBounds`로 맞춥니다. 교회가 한 곳이면 점 하나에 맞춰 너무 가까워집니다.
  - 카카오맵 공식 문서(ctx7 `/websites/apis_map_kakao_web`)의 `map.setCenter(latlng)`, `map.setLevel(level, options)`를 씁니다.
  - 지금 타입(`kakao.ts`)과 가짜 SDK(`e2e/kakao-fake.js`)에는 둘 다 없습니다.
  - `onSelect`가 없으면 핀은 교회 이름이 붙은 그림(`role="img"`)이라, 상세 페이지 지도에 그대로 맞습니다.
- **입구:**
  - 추천 카드(`ChurchCard`)는 홈에서만 씁니다. 사진 위에 하트 버튼이 있습니다.
  - 지도 목록 줄(`ChurchListItem`)은 줄 전체가 고르기 버튼입니다. 사진 카드는 핀 버튼 안에 있습니다. 그래서 링크를 그 안에 넣을 수 없고, 버튼과 나란히 둬야 합니다.
- **재사용:**
  - 행사 카드 `event/EventCard`, 공지 줄 `common/ArticleRow`, 태그 `common/TagList`
  - 대표자 관리의 교회 정보 목록(담임목사·지역·주소·교인 수, `admin/MyChurchPanel.tsx`)을 `church/ChurchFacts`로 올려 두 화면이 같이 씁니다.
- **배운 점:**
  - 역할 이름은 기본이 부분 일치라 `exact`로 찾습니다.
  - 장식 이미지는 `img` 역할이 없습니다.
  - 테스트는 개발 서버를 끈 뒤 돌립니다.
  - 임시 스크립트는 scratchpad에서 표준 입력으로 실행합니다.

## 결정
- **질문과 답:**
  - 입구: 추천 카드, 그리고 지도에서 고른 교회(목록 줄과 사진 카드)
  - 위치 지도: 넣기
- **정한 것:**
  - e2e `workers: 3`. `actionTimeout`(5초)은 그대로 둡니다.
  - 페이지 구성(위에서 아래로):
    - 교회 이름(`h1`), 소개 한 줄, 지역 배지, 태그
    - 사진과 교회 정보(`ChurchFacts`)
    - 위치 지도와 "교회 지도에서 보기" 링크(`/map?region=<지역>`)
    - 다가오는 행사(`EventCard` 격자)
    - 공지(`ArticleRow`)
    - 행사·공지가 없으면 빈 안내를 보여 줍니다.
  - 커뮤니티 글은 넣지 않습니다. 상위 계획서가 "소개, 행사, 공지"이기 때문입니다.
  - 지도는 받은 교회가 한 곳이면 `setCenter`와 `setLevel(4)`로 맞춥니다. 수준 4는 동네가 보이는 정도이고, 이름표가 보이는 수준(8 이하)입니다. 진짜 지도에서 보고 조정합니다. 그 밖의 경우는 지금처럼 `setBounds`입니다. 맞춘 뒤 `idle`을 직접 일으키는 것도 그대로입니다.
  - 추천 카드:
    - 교회 이름을 링크로 하고, 링크의 누를 수 있는 영역을 카드 전체로 넓힙니다(stretched link).
    - 하트 버튼은 그 위에 올려(`relative z-10`) 따로 누를 수 있게 둡니다.
  - 지도 페이지:
    - 고른 교회의 목록 줄 아래에 "자세히 보기" 링크를 둡니다. 화면 읽기 프로그램에는 "<교회> 자세히 보기"로 읽힙니다.
    - 지도의 사진 카드도 핀 버튼 밖으로 꺼내 같은 이름의 링크로 만듭니다.
  - branch는 `feat/church-detail-page`입니다. 커밋은 사용자가 요청할 때 합니다.

## 리스크와 멈출 조건
- **404 응답 코드:** 요청 때 그리는 페이지에서 `notFound()`가 첫 바이트 전에 던져지면 404입니다. 200이 나오면 문서로 원인을 확인하고, 테스트는 "404 화면"으로 바꾸지 않고 상태 코드를 맞추는 쪽으로 고칩니다.
- **카드 전체 링크와 하트:** 넓힌 링크가 하트를 덮으면 하트가 눌리지 않습니다. 하트를 `z-10`으로 올리고, e2e의 하트 테스트로 확인합니다.
- **지도 오버레이 안의 링크:** 진짜 SDK에서 오버레이 링크 클릭이 지도 끌기와 부딪힐 수 있습니다(`clickable: true`). 3000에서 확인하고, 안 되면 사진 카드 링크는 빼고 목록 링크만 둔 뒤 변경 이력에 적습니다.
- **workers 3으로도 흔들림:** 3번 중 실패가 나오면 원인을 다시 좁히고 사용자에게 알립니다. 설정을 더 바꾸는 것은 사용자 결정입니다.
- 계획 밖 결정이 필요해지면 다음 task로 넘어가지 않고 사용자에게 묻습니다.
