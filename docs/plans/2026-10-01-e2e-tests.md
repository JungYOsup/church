# 화면 동작 점검 17개를 저장소의 Playwright 테스트로 옮기기

## Context
- 3단계에서 헤더·히어로를 만든 뒤 Playwright로 동작 17개를 점검했습니다. 그 스크립트(`scratchpad/e2e/check.mjs`)는 **세션 임시 폴더**에 있어서 곧 사라집니다. 사용자, 다른 세션, 나중의 CI도 쓸 수 없습니다.
- 저장소에 정식 테스트로 옮겨 `npm run test` 한 줄로 언제든 다시 돌리게 합니다. 다음 기능(통계 카드 등)을 붙일 때 헤더·메뉴가 깨지면 바로 잡힙니다.
- 범위는 **동작 테스트만**입니다(메뉴 이동, 활성 표시, 모바일 메뉴, 드롭다운, 버튼 이동, 가로 스크롤, 폰트, 콘솔 에러). 보이는 모습(색·간격)을 보는 스크린샷 비교는 디자인이 굳은 뒤에 합니다.
- 6축으로는 검증(VF-01 테스트 존재+통과)과 구조(ST-02 테스트 폴더, ST-03 test 명령)를 채웁니다.

## 확인한 사실
- **브라우저:** Playwright 최신(1.63.0)은 크롬 rev 1243을 쓰는데, 캐시에는 rev 1228만 있습니다. 설치된 **Google Chrome**을 쓰면(`channel: "chrome"`) 약 150MB 다운로드 없이 바로 돌릴 수 있습니다. 3단계 점검도 이 방식으로 돌렸습니다. CI를 붙일 때는 `npx playwright install chrome`을 추가하면 됩니다.
- **서버 충돌:** Next 16에서는 같은 프로젝트에 `next dev`를 두 번 띄우면 두 번째가 실행되지 않습니다(`.next/dev/lock`). 사용자의 개발 서버(3000)와 부딪히지 않도록 테스트는 **빌드 후 `next start`를 3100 포트로** 띄웁니다. dev와 build는 출력 폴더가 분리되어 있어 함께 돌아도 됩니다.
- **Playwright 기능(공식 문서):** `webServer`로 테스트 전에 서버를 띄우고 끝나면 내리며, `use.baseURL`로 상대 경로를 씁니다. `test.extend`의 `{ auto: true }` fixture로 모든 테스트에 콘솔 에러 검사를 자동으로 붙일 수 있습니다.
- **타입 검사:** `tsconfig.json`이 `**/*.ts`를 포함하므로 테스트 파일도 `npm run build` 때 타입 검사를 받습니다. `@playwright/test`를 devDependency로 설치하면 됩니다.

## 만들 것

### 1. 설치와 설정
- `npm i -D @playwright/test`
- `playwright.config.ts`
  - `testDir: "./e2e"`, `reporter: "list"`
  - `use`: `baseURL: http://localhost:3100`, `locale: "ko-KR"`, `trace: "retain-on-failure"`
  - `projects`: `chrome` 하나 (`devices["Desktop Chrome"]` + `channel: "chrome"`)
  - `webServer`: `npm run build && npm run start -- -p 3100`, `url`, `timeout: 180_000`, `reuseExistingServer: false`(항상 새 빌드로 시험)
- `package.json` scripts
  - `"test:e2e": "playwright test"`
  - `"test": "npm run test:e2e"` (나중에 단위 테스트가 생기면 여기에 함께 묶음)
- `.gitignore`: `/test-results/`, `/playwright-report/`, `/blob-report/`, `/playwright/.cache/`

### 2. 테스트 (`e2e/`, 기존 17개를 그대로 옮김)
- **`e2e/fixtures.ts`:** 모든 테스트에 자동으로 붙는 콘솔 에러 검사. 테스트가 끝날 때 `console.error`나 `pageerror`가 하나라도 있으면 실패합니다.
- **`e2e/home.spec.ts` (6개)**
  - 375 / 768 / 1440px에서 가로 스크롤 없음 (3)
  - 본문에 Pretendard 폰트 적용 (1)
  - 히어로 "교회 찾기" → `/map`, "우리 교회 등록" → `/admin` (2)
- **`e2e/navigation.spec.ts` (11개)**
  - 데스크톱(1440px): 메뉴 6개를 각각 누르면 해당 경로로 이동하고 `aria-current="page"`가 그 메뉴에 붙음 (6)
  - 하위 페이지 탭 제목이 "행사 | 함께하는 교회" (1)
  - 프로필 메뉴를 열면 "로그아웃" 항목이 보임 (1)
  - 모바일(375px): 데스크톱 메뉴가 숨겨짐 (1), 햄버거 메뉴에서 "공지"를 누르면 `/notices`로 이동하고 메뉴가 닫힘 (1), 다시 열면 "공지"가 현재 메뉴 (1)
- 기대하는 메뉴 목록은 `src/lib/navigation.ts`에서 가져오지 않고 **테스트에 직접 적습니다.** 테스트가 명세 역할을 해서, 메뉴 이름이 실수로 바뀌면 잡아낼 수 있습니다.
- 테스트 이름은 한국어 문장으로, 무엇을 보장하는지 읽히게 씁니다.

### 3. 하네스 반영
- **`.claude/hooks/verify-on-stop.sh`:** 감시 경로(`APP_PATHS`)에 `e2e`, `playwright.config.ts`를 추가합니다. 테스트 파일도 build 타입 검사 대상이라, 바뀌면 DoD hook이 돌아야 합니다.
- **`CLAUDE.md`**
  - Architecture에 `e2e/`(Playwright 동작 테스트) 한 줄을 추가합니다.
  - Commands에 `npm run test`(빌드 후 3100 포트에서 서버를 띄워 동작 테스트, 약 30초)를 추가합니다.
  - DoD를 다음처럼 바꿉니다.
    - "`npm run test` 통과 (커밋 전, 또는 화면 동작을 바꿨을 때)"
    - "보이는 모습(색·간격·디자인)은 375 / 768 / 1440px에서 직접 확인한다." 동작은 테스트가 보므로, 사람이 보는 범위를 모습으로 좁힙니다.
- 이 계획을 `docs/plans/2026-10-01-e2e-tests.md`로 저장합니다.
- 응답을 끝낼 때 지도 반영 hook이 갱신을 요청할 것입니다. 지도 최신본(Version 4)을 read해서 파일 목록에 `e2e/`·`playwright.config.ts`를 추가하고 "다음에 할 일"을 고칩니다. 점수와 체크 상태는 진단 전이므로 그대로 둡니다.

## 검증
1. `nvm use && npm run test`로 **17개 통과**를 확인합니다. 사용자 개발 서버(3000)를 켠 상태에서도 돌아가는지 봅니다.
2. **일부러 깨뜨려 보기:** `src/lib/navigation.ts`의 "행사"를 "행사안내"로 바꾸면 메뉴 테스트가 실패하고 무엇이 틀렸는지 메시지가 나오는지 확인한 뒤 되돌립니다.
3. DoD `npm run lint && npm run build`가 통과하는지 봅니다. Stop hook도 자동으로 확인합니다.
4. 커밋은 요청을 받으면 합니다. 다른 세션에서 만든 지도 반영 hook 작업(아직 커밋 안 됨)과는 **커밋을 나눕니다.**
